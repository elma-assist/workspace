# Правила разработки Elma

Проект разрабатывается с нуля. Обратная совместимость со старыми схемами,
API и выданными ссылками сейчас не требуется. При рефакторинге заменяй прежнюю
реализацию новой, обновляй вызовы и тесты; не добавляй legacy-ветки, алиасы,
редиректы или адаптеры ради сохранения старого поведения. Это разрешение менять
контракты, а не удалять пользовательские данные без необходимости.

При изменениях интерфейса соблюдай [стандарты UI](docs/ui-standards.md).
Они обязательны для админки, чата, виджета и лендинга:

- Кнопка, запускающая операцию с ожиданием результата, показывает спиннер поверх
  самой кнопки, сохраняет размеры и блокирует повторный запуск до завершения.
- Каждое модальное или дополнительное окно имеет понятный URL. Прямое открытие,
  обновление страницы и переходы назад/вперёд восстанавливают соответствующее окно
  и выбранный объект с проверкой доступа.

Используй `apps/web/components/AsyncAction.tsx` для Button и ActionIcon:
асинхронные `onClick` должны возвращать Promise. Для отправки HTML-форм явно
передавай `loading` и блокируй повторный submit в обработчике. Не меняй текст
кнопки на «Saving…» во время загрузки.

Для окон используй `apps/web/hooks/useRouteState.ts`: идентификаторы и режимы
живут в URL, данные загружаются через API. Не сохраняй токены сессий или ответы
форм в query-параметрах. URL-состояние iframe синхронизируется с родительским
виджетом в `packages/agent-widget/widget.js`.

Требования к продукту и качеству: [спецификация](docs/mvp-system-requirements.md).
