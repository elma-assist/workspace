# Доработки интерфейса после демонстрации

Статус: реализовано в локальной сборке. Проверены основные пользовательские сценарии, клавиатурная навигация, мобильная компоновка, Markdown и голосовой индикатор.

## 1. Готовая основа админки

- Использовать готовую библиотеку компонентов вместо самописных базовых элементов. Предложенная основа — Mantine для Next.js.
- Привести навигацию, формы, модальные окна, таблицы и действия к единому стилю и поведению.
- Убрать рекламные слоганы из рабочего интерфейса; показывать полезные сведения об агенте вместо обрывка системной инструкции.
- Сделать основные действия понятными без угадывания назначения иконок.
- Проверить клавиатурную навигацию, фокус в диалогах, адаптивность и существующие пользовательские сценарии.
- Использовать стандартную тему Mantine и её готовые токены цветов, типографики, отступов, радиусов, теней и размеров. Не придумывать собственную палитру и шкалы, не расставлять произвольные значения на отдельных экранах.
- Хранить общую настройку темы в одном переиспользуемом модуле; админка, страницы организаций и интерфейс чата/виджета должны использовать одну основу. Будущие интерфейсы подключают тот же модуль.
- Использовать штатные варианты компонентов. Собственные стили нужны только для специфичной компоновки и визуализации голоса, с опорой на токены библиотеки.
- Начатую локальную настройку темы пересмотреть по этому правилу: стандартные значения библиотеки имеют приоритет над вручную выбранными шрифтами и оформлением.

Текущее состояние: перенос завершён, контейнер web пересобран. Используются стандартная тема Mantine, AppShell, Breadcrumbs, Modal, поля, кнопки, карточки и таблицы. Старые базовые CSS-файлы удалены.

## 2. Обратная связь во время разговора

- Компактное облако с частицами реагирует на реальную громкость микрофона пользователя и речи агента. Измерение выполняется через Web Audio, анимация — на Canvas в фиксированной области.
- Единый индикатор заменяет две отдельные шкалы. Подписи объясняют ход разговора, а не устройство аудиоканалов.
- Подписи имеют задержку смены и плавное появление; энергия анимации сглажена. Высота блока постоянна и меньше 140 px в проверенном виджете.
- Явно различать состояния: подключение, готов слушать, пользователь говорит, агент обрабатывает запрос, агент отвечает, микрофон выключен, переподключение, ошибка.
- Пользователь должен понимать, что агент занят и запрос не потерялся.
- Более конкретную активность (например, поиск по базе знаний) показывать только при наличии реального события от сервера, не имитировать работу.
- Сохранять текстовые подписи состояний: анимация дополняет обратную связь, но не заменяет её. Учитывать настройку уменьшения движения.
- Проверить, что визуализация и состояния корректно меняются при перебивании агента и переключении текста/голоса в одной беседе.

Статус: реализовано и проверено.

## 3. Скачивание документов

- В списке документов заменить текстовую кнопку Download на компактную иконку скачивания.
- Сохранить подсказку при наведении и доступное название кнопки для клавиатуры и скринридеров.
- Использовать готовый компонент кнопки с иконкой из выбранной UI-библиотеки.

Статус: реализовано и проверено.

## 4. Отдельная страница организаций

- После обычного входа открывать страницу «Мои организации» со списком доступных пользователю организаций и действием создания организации.
- Выбор организации открывает её отдельное рабочее пространство по адресу со slug организации.
- Внутри рабочего пространства показывать название текущей организации без выпадающего переключателя и без дополнительных элементов выбора организации сверху.
- Постоянно показывать хлебные крошки: «Мои организации → Название организации → Раздел». Родительские уровни — ссылки, текущая страница — текст. Ссылка «Мои организации» возвращает к общему списку; отдельная дублирующая кнопка возврата не нужна.
- Сохранять прямые ссылки на конкретную организацию с проверкой доступа пользователя.
- При переходе между организациями через общую страницу очищать состояние предыдущего рабочего пространства и закрывать его активную сессию разговора.

Статус: реализовано и проверено.

## 5. Markdown в ответах агента

- Отображать Markdown в сообщениях агента вместо буквальной разметки: выделение, списки, ссылки, заголовки, цитаты, блоки кода и таблицы.
- Использовать готовый React Markdown-рендерер, без самописного парсинга. Не исполнять HTML или скрипты из ответов модели.
- Применить единый компонент отображения к живому чату, встроенному виджету и истории разговоров; оформление использует общие токены UI-библиотеки.
- Корректно отображать поступающий по частям текст во время генерации, длинные ссылки, таблицы и блоки кода на узких экранах.

Статус: реализовано и проверено.

## Проверка

- TypeScript и production-сборка Next.js проходят.
- 7 браузерных сценариев: регистрация и организации, знания/чат/RAG/расходы, встроенный и внешний виджеты, клавиатура/мобильная компоновка, Markdown в истории, переключение текста/голоса в одной сессии.
- 4 проверки отображения: структура и безопасность Markdown, незавершённый потоковый Markdown, уровень звука и различимость состояний.
- Голосовой браузерный тест использует синтетический микрофон и реальный ответ модели, проверяет наличие звука, ненулевую реакцию индикатора и постоянную высоту панели. Настоящий микрофон пользователя тестом не записывается.
- Голосовой компонент учитывает системную настройку уменьшения движения. Контексты анализа звука и цикл анимации освобождаются при закрытии.
