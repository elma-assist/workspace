# Elma landing page

English/German landing for German residential property-management companies. Seven
sections: delegation hero, team overload, resident/owner perspective, workflow,
illustrative heating request, parallel benefits, and the real demo.

Elma answers from company knowledge, collects and prefills request details, and
lets residents review and submit. Staff review submitted requests and update
statuses. Coordination means supporting this staff workflow; the page does not
promise automated assignment, contractor booking or completed repairs.

Survey claims link directly to VDIV's 19 August 2026 release (62.1% of surveyed
companies overloaded) and Matera's 2022 YouGov survey (one in five German apartment
owners dissatisfied; 1,001 respondents, representative weighting). The former
is not evidence that resident requests specifically caused the overload.

The heating illustration uses fictional details and is explicitly labelled.
Its animation supports pause, manual steps, reduced motion and offscreen pause.
The hero is a static conversation illustration. Both Try Elma buttons load the
actual existing widget through `/api/demo` and `/widget.js`; no simulated agent
runtime is used. Loading locks both buttons with stable dimensions and an inline
spinner. Widget routing and conversation persistence remain in the shared widget.

Files: `apps/landing/public/index.html`, `landing.css`, `landing.js`,
`workflow.css`, `workflow.js`, `locale.js`. The existing icon sprite is generated by
`scripts/build-widget.mjs`. Landing browser coverage is in
`tests/browser/landing.spec.ts` and `tests/browser/landing-locale.spec.ts`.

## Language selection

English is the initial default, including in a German-language browser. The
compact globe + EN/DE trigger opens an English/Deutsch menu with native language
labels and `menuitemradio` selected state. Arrow keys, Home/End, Enter/Space,
Escape, Tab and outside clicks support selection and dismissal. This transient
selection menu does not represent a separate page or dialog and does not change
the URL. On narrow screens the workspace link uses its icon and accessible name.
Explicit selection is stored in `localStorage` under `elma-landing-language`;
blocked storage leaves the switcher usable for the current page. Invalid saved
values fall back to English. Only the language preference is stored by this code.

`locale.js` translates original landing text nodes and accessibility attributes,
updates document language, title and description, and signals dynamic animation
labels and error states. English source strings are the translation keys; add
new copy to the German dictionary when changing the page. Existing controls and
their event listeners are preserved during a switch.

The existing shared widget has no locale API. Its English controls and runtime
are unchanged; localized demo copy explains that visitors may converse with
Emma in English or German. Choosing German on the landing does not automatically
change the agent's language or restart an existing conversation.
