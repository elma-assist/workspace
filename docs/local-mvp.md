# Elma: локальная версия

## Запуск и вход

Из корня проекта:

```sh
./scripts/start.sh
```

На macOS можно дважды нажать `Start Elma.command`. Остановка — `Stop Elma.command`
или `./scripts/stop.sh`. Данные остаются в Docker volumes.

- Лендинг и публичный агент: http://localhost:8180
- Рабочее пространство: http://localhost:8180/app
- Демо-организация: http://localhost:8180/app/nordhaus/agents
- Документация API: http://localhost:8180/api/docs
- Тестовые логины и случайный пароль: [локальный файл доступа](../infra/local/demo-access.md).

Демо создаётся автоматически: Nordhaus, агент Emma, администратор, сотрудник,
две текстовые инструкции на английском и немецком и форма Repair request. Seed можно запускать повторно:
он не размножает записи и не перезаписывает отредактированных агентов.

Ключи провайдеров читаются только серверными компонентами из `.env.local`:
`MISTRAL_API_KEY` и `OPENROUTER_API_KEY`. Пример формата — `.env.example`.
Внутренние пароли и ключи установки генерируются один раз в `infra/local`.

## Что можно проверить

1. После входа открыть «My organizations», создать или выбрать организацию. Возврат — через хлебные крошки, без выпадающего переключателя.
2. Создать базу знаний, загрузить `.txt`/`.md` или вставить текст; дождаться `ready`.
3. Создать агента с инструкцией, моделью, языком и выбранными базами знаний.
4. Открыть чат, задать вопросы, включить голос в том же разговоре.
5. Пригласить сотрудника и назначить ему агентов. Для локального режима интерфейс
   выдаёт одноразовую ссылку приглашения; отправка внешней почты не подключена.
6. Открыть историю разговоров, найденные источники и расход организации.
7. В настройках виджета указать точный origin сайта, включить публикацию и получить
   код вставки. Гостевые разговоры сохраняются в организации владельца агента.

8. Открыть Forms, создать шаблон и назначить его агенту. В демо Emma уже назначена
   форма Repair request. Попросить открыть её, сообщить только имя: поле должно
   заполниться без ожидания email и адреса, с зелёной отметкой Saved.
9. Добавить остальные сведения и фото, проверить и отправить заявку. В Requests
   изменить статус. В виджете открыть My requests и увидеть отправленную заявку.

Подробности, ограничения и модель доступа: [Формы и заявки](forms-design.md).

Проверочные вопросы для Emma:

- “When is the next resident meeting and where is it?”
- “Wann sind bei Nordhaus die Ruhezeiten?”

Сотрудники видят только назначенных агентов, но могут читать все разговоры своей
организации. Публикация новых агентов выключена до явного включения владельцем.

## Компоненты

| Каталог / сервис | Назначение |
|---|---|
| `apps/web` | Next.js + стандартная тема Mantine: вход, организации, администрирование и панель виджета |
| `apps/landing` | Отдельный лендинг на nginx |
| `packages/agent-widget` | Скрипт для встраивания агента на сайт |
| `services/api` | FastAPI: организации, права, конфигурации, знания, история, usage |
| `services/agent-worker` | LiveKit Agents, Mistral STT/LLM/TTS, получение RAG-контекста |
| `indexer` | Отдельный процесс индексации текстов через OpenRouter |
| `event-relay` | Доставка событий разговора и расходов из PostgreSQL outbox, в том числе когда нет активных агентов |
| `packages/contracts` | Общие Pydantic-схемы, OpenAPI и сгенерированные TypeScript-типы |
| `infra` | Docker Compose, маршруты Traefik, закрытая конфигурация установки |
| PostgreSQL + pgvector | Данные приложения, документы, векторы, история и ledger |
| SeaweedFS | S3-хранилище оригиналов документов |
| LiveKit Server | Сигналинг, комнаты, WebRTC |

HTTP и WebSocket идут через Traefik на локальном порту 8180. WebRTC использует
локальные порты 7881/TCP и 7882/UDP. PostgreSQL и служебные порты хранилища не
опубликованы на хосте. Подписанные S3-ссылки используют `files.localhost:8180`.
LiveKit объявляет loopback и внутренние Docker-адреса, чтобы соединялись и браузер
на macOS, и воркер внутри контейнера.

## Учёт расходов

Сохраняются первичные единицы: токены LLM/embeddings, секунды STT и символы TTS.
У каждой операции есть организация, агент/разговор, идентификатор, исходные метрики,
версия тарифа, себестоимость и клиентская цена. Повторная доставка одного события
не создаёт повторное списание. Расход embeddings фиксируется отдельно от транзакции
индексации, чтобы не потерять его при последующей ошибке обработки документа.

Начальный тариф — опубликованная цена провайдера с коэффициентом 1,20.
`BILLING_MULTIPLIER` и `BILLING_TARIFF_VERSION` можно задать в `.env.local`;
это влияет только на новые операции. Один отображаемый кредит соответствует $0,01.
Отрицательный баланс разрешён. Месячный фильтр использует UTC; CSV содержит полный
ledger выбранного периода, а экран — последние 200 операций.

Цена провайдера рассчитывается по опубликованным ставкам, а не по уже выставленному
инвойсу. Перед выставлением реального счёта нужно сверить её с провайдером:
скидки, Enterprise-тарифы и налоги в текущий расчёт не входят. Для неизвестной ставки
сохраняется `unpriced`, а не нулевая стоимость.

Ставки сверены 12 сентября 2026 года с [ценами Mistral](https://mistral.ai/pricing/api/)
и каталогом embeddings OpenRouter. LiveKit Server закреплён на версии 1.13.6,
Python-зависимости — в `requirements.lock`, frontend — в `package-lock.json`.

## Проверки и резервные копии

```sh
npm ci
uv sync --frozen
uv pip install -r services/api/requirements.lock
npx playwright install chromium webkit
./scripts/test.sh
```

Браузерные тесты используют реальные платные модели. Для отдельного полного
голосового теста с синтетической речью:

```sh
.venv/bin/python scripts/test_voice.py
```

Он проверяет WebRTC → распознавание → RAG → ответ → синтез на двух языках и сохраняет
аудио и результаты в `artifacts`. Микрофон пользователя этот тест не записывает.
Проверки Markdown и состояний интерфейса: `npm run test:ui`. Браузерный тест проверяет переключение текста/голоса в одной беседе с синтетическим микрофоном, реакцию облака на звук и постоянную высоту индикатора.

Мобильные сценарии запускаются командой
`npx playwright test --project=mobile-chromium --project=mobile-webkit --project=mobile-voice`.
Проверяются размеры 320×640, 360×740, 390×844 и 768×1024, поворот экрана,
доступность действий в прокручиваемых таблицах, диалоги и чат при уменьшении высоты
окна. Голосовой сценарий использует синтетический микрофон Chromium. Это браузерная
эмуляция: настоящая экранная клавиатура, Safari на физическом iPhone и аппаратные
микрофоны требуют проверки на устройствах. Скриншоты сохраняются в `artifacts/mobile`.

Иконки приложения, лендинга и виджета берутся из одного установленного набора
`lucide-react`. `npm run build:widget` генерирует SVG-спрайт лендинга и автономный
скрипт виджета с выбранными SVG; React на сайте клиента не требуется. Docker-сборка
лендинга запускает эту команду автоматически. Исходники виджета находятся в
`packages/agent-widget/widget.js` и `widget.css`, сборщик — `scripts/build-widget.mjs`.
Сгенерированные файлы вручную редактировать не следует.

RAG добавляет выдержки только в отдельную копию запроса внутри `llm_node`, общую
для текста и голоса. Служебные данные не записываются как реплики ассистента и не
меняют исходное сообщение пользователя. Тесты воркера проверяют изоляцию контекста,
сохранение инструкций Mistral, пустой результат, ошибку поиска и следующий вопрос.
Браузерный и голосовой прогоны также проверяют отсутствие служебных вставок в ответах.
После исправления передачи RAG-контекста прошли 5 тестов воркера, проверка типов,
3 браузерных сценария и английский голосовой сценарий. Немецкий синтетический
голосовой прогон не прошёл: STT исказил вопрос (например, «Ruhezeiten» → «hohe Zeiten»).
Текстовый немецкий RAG работает; распознавание немецкой речи требует отдельной проверки,
включая качество тестового синтеза, который сейчас использует английский голос.

Изменённые контракты обновляются командой `./scripts/contracts.sh`.

```sh
./scripts/backup.sh
python3 scripts/check_restore.py
```

Копия содержит PostgreSQL dump и ZIP объектов S3. Проверка восстановления создаёт
отдельную временную базу и S3 bucket, загружает данные, проверяет контрольные суммы
и удаляет только эти тестовые ресурсы. Копии находятся в `infra/local/backups`.

## Границы текущей поставки

Это локальная сборка для демонстрации и проверки продукта. Внешнее развёртывание,
публичные домены/TLS/TURN, реальная почтовая доставка, платежи и налоговые инвойсы
ещё не подключены. Формы, PDF/OCR, телефония, Temporal и Kanban исключены из этого
этапа по согласованным решениям.

Проверены одиночные сессии в Chromium/WebKit и синтетический голос. Массовая нагрузка,
физические микрофоны/гарнитуры и браузеры на настоящих телефонах требуют отдельного пилотного
прогона. Голосовые ответы в локальном контрольном прогоне начинались примерно
через 3,6–3,7 секунды после конца вопроса; это два замера, не гарантия p95.

Подготовлен CI для типов, контрактов, миграций и интеграционных тестов. Он ещё не
запускался на внешнем CI-сервере: проект находится локально. Полный аудит лицензий
транзитивных зависимостей и production security review остаются перед внешними пилотами.
Сгенерированные OpenAPI/TypeScript-артефакты могут быть длинными; прикладные модули
разделены по ответственности и остаются небольшими.
